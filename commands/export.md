# Haytham: Export Validation Report

You are exporting Phase 1 outputs to a demos repository for sharing with founders.

## Prerequisites

Verify these files exist:
- `.haytham/session/phase-1-why/validation-report.md`
- `.haytham/session/phase-1-why/validation-report.json`

If either is missing:
> Phase 1 must be completed first. Run `/haytham:validate` to generate a validation report.

## Argument Parsing

Parse optional flags from the argument:
- `--target <path>`: Target demos repository root. Default: `../haytham-demos`
- `--slug <name>`: Directory name for this report under `reports/`. If omitted, auto-generate (see below).
- `--commit`: Auto-commit to the demos repo after export.
- `--pdf`: Also generate a PDF of the validation report.

## Slug Generation

If `--slug` was not provided, generate one automatically:

1. Read `.haytham/project.yaml`
2. If `source.type` is `reddit_post`: extract the post ID from `source.url` path -> `reddit-{id}`
3. If `source.type` is `github_repo`: extract owner/repo from `source.url` -> `github-{owner}-{repo}`
4. If `source.type` is `text` or absent: take the first 50 characters of the `idea:` field, lowercase, replace spaces and special characters with hyphens, strip trailing hyphens

If `{target}/reports/{slug}/` already exists, append a numeric suffix (e.g., `reddit-1abcdef-2`).

## Export Steps

### Step 1: Validate Target

Check if the target directory exists using Bash:
```bash
ls [target]
```

If it does not exist:
> Target directory `[target]` does not exist. Create it with `git init [target]`, or specify a different path with `--target`.

If `[target]/reports/` does not exist, create it:
```bash
mkdir -p [target]/reports
```

### Step 2: Copy Files

Create `{target}/reports/{slug}/` directory.

Read the following files and write them to the target:
- `.haytham/session/phase-1-why/validation-report.md` -> `{target}/reports/{slug}/validation-report.md`
- `.haytham/session/phase-1-why/idea-analysis.md` -> `{target}/reports/{slug}/idea-analysis.md`
- `.haytham/session/phase-1-why/concept-anchor.json` -> `{target}/reports/{slug}/concept-anchor.json` (skip if file does not exist)

### Step 3: Generate Outreach Summary

Launch an **outreach-summarizer** agent with this task:
> Read the validation report from `.haytham/session/phase-1-why/validation-report.md`, structured data from `.haytham/session/phase-1-why/validation-report.json`, idea analysis from `.haytham/session/phase-1-why/idea-analysis.md`, and project metadata from `.haytham/project.yaml`. Write the outreach summary to `{target}/reports/{slug}/summary.md`.

After the agent completes, read `{target}/reports/{slug}/summary.md` and verify it is under 50 lines. If it exceeds 50 lines, tell the user:
> **Warning:** Summary exceeded 50 lines. You may want to trim it before sharing.

### Step 4: Generate source.yaml

Read `.haytham/project.yaml` and `.haytham/session/phase-1-why/validation-report.json`. Read `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/marketplace.json` for the version.

Write `{target}/reports/{slug}/source.yaml`:
```yaml
idea: |
  [from project.yaml idea field]
source_url: [from project.yaml source.url, or null]
source_type: [from project.yaml source.type, or "text"]
fetched_at: [from project.yaml source.fetched_at, or null]
exported_at: [current ISO timestamp]
haytham_version: [from marketplace.json plugins[0].version]
verdict: [from validation-report.json recommendation]
composite_score: [from validation-report.json composite_score]
```

### Step 5: Generate Per-Report README

Write `{target}/reports/{slug}/README.md`:

```markdown
# [First line of idea text, truncated to 80 chars]

**Verdict:** [recommendation from validation-report.json]
**Composite Score:** [composite_score]/5.0
**Source:** [source_url or "Manual input"]
**Generated:** [exported_at timestamp]
**Haytham Version:** [version]

## Files

| File | Description |
|------|------------|
| [summary.md](summary.md) | One-page summary with key findings (start here) |
| [validation-report.md](validation-report.md) | Full validation report with competitive analysis and risk profile |
| [idea-analysis.md](idea-analysis.md) | Structured idea expansion and concept health signals |
| [concept-anchor.json](concept-anchor.json) | Concept invariants and strategic signals (if available) |
| [source.yaml](source.yaml) | Provenance metadata |
```

### Step 6: Update Index

Read `{target}/README.md`. If it exists and contains a reports table (a markdown table with columns Report, Idea, Verdict, Source), add a new row to it.

If the file does not exist or does not contain a reports table, write it:

```markdown
# Haytham Demo Reports

Validation reports generated by [Haytham](https://github.com/arslan70/haytham), a lifecycle control plane for AI-built products.

| Report | Idea | Verdict | Score | Source |
|--------|------|---------|-------|--------|
| [{slug}](reports/{slug}/) | [first 60 chars of idea] | [verdict] | [score]/5.0 | [source_type] |
```

### Step 7: PDF Generation (if --pdf)

If `--pdf` flag was passed:

1. Check if pandoc is installed:
   ```bash
   command -v pandoc
   ```
2. If not installed:
   > pandoc is not installed. Install it with `brew install pandoc` (macOS) or `apt install pandoc` (Linux) and re-run with `--pdf`.

   Skip PDF generation but continue with the rest of the export.

3. If installed, generate the PDF:
   ```bash
   pandoc '{target}/reports/{slug}/validation-report.md' -o '{target}/reports/{slug}/validation-report.pdf' -V geometry:margin=1in -V fontsize=11pt --metadata title='Validation Report: {slug}'
   ```

4. If the pandoc command fails (e.g., missing LaTeX engine), try the fallback:
   ```bash
   pandoc {target}/reports/{slug}/validation-report.md -o {target}/reports/{slug}/validation-report.pdf --pdf-engine=wkhtmltopdf
   ```

5. If both fail, tell the user:
   > PDF generation failed. You may need to install a PDF engine (`brew install basictex` or `brew install wkhtmltopdf`). The markdown report has been exported successfully.

### Step 8: Commit (if --commit)

If `--commit` flag was passed:
```bash
git -C '{target}' add 'reports/{slug}/' README.md && git -C '{target}' commit -m 'Add validation report: {slug}'
```

If the commit fails (e.g., not a git repo), tell the user:
> Could not commit. The target directory may not be a git repository. Files have been exported successfully.

## Completion

Tell the user:
> **Export complete.**
> - Report: `{target}/reports/{slug}/`
> - Summary for outreach: `{target}/reports/{slug}/summary.md`
> - Files: summary.md, validation-report.md, idea-analysis.md, concept-anchor.json, source.yaml [, validation-report.pdf if generated]
> [- Committed to demos repo] (if --commit was used and succeeded)
>
> Share with the founder: point them to the report directory on GitHub, or send individual files.
