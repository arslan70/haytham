# Validation

## Purpose

This domain covers Phase 1 (WHY) and its public-facing variants. The user submits an idea or URL; Haytham extracts the concept anchor, researches the market and competitors in parallel, compiles a neutral brief, and a single synthesizer produces a GO/PIVOT/NO-GO recommendation. Outputs can be exported as a shareable report or generated unattended via the demo pipeline. This is the entry point of Genesis and the only phase that touches web search.

### Requirement: Idea Validation Pipeline [CAP-F-001]

The system SHALL accept a startup idea as free text or a URL, SHALL run idea analysis followed by parallel market and competitor research, SHALL compile a neutral research brief for founder review, and SHALL produce a validation report with a GO, PIVOT, or NO-GO recommendation backed by upstream evidence.

#### Scenario: Founder validates a free-text idea

- **Given** a Claude Code session with the haytham plugin installed and no prior pipeline state under `.haytham/session/`
- **When** the founder runs `/haytham:validate "an occasion-based gift delivery service for diaspora communities"`
- **Then** the system writes `.haytham/session/phase-1-why/concept-anchor.json` with invariants, identity, intent, term flags, founder profile, and strategic signals, and writes a validation report with an explicit GO, PIVOT, or NO-GO verdict

#### Scenario: Market and competitor research run in parallel

- **Given** idea analysis has completed and the concept anchor is written
- **When** the orchestrator dispatches market and competitor research
- **Then** the market-researcher and competitor-researcher agents run in a single parallel tool call, each producing its own output file, neither depending on the other's output

#### Scenario: Synthesis is single-agent with full context

- **Given** market research and competitor research outputs both exist
- **When** the report-synthesizer agent runs
- **Then** the agent reads the full upstream context (concept anchor, idea analysis, market research, competitor research, research brief) and produces one validation report with a single explicit verdict, not a multi-step pipeline of partial syntheses

#### Scenario: Batch mode skips review gates

- **Given** the founder runs `/haytham:validate "an idea" --batch`
- **When** the pipeline reaches a phase boundary that would normally prompt for approval
- **Then** the orchestrator auto-approves the gate and continues without interactive review

#### Scenario: NO-GO verdict stops the pipeline

- **Given** the report-synthesizer produces a NO-GO verdict
- **When** the orchestrator reaches the post-Phase-1 gate
- **Then** the pipeline surfaces the verdict and rationale and stops, requiring an explicit founder override to continue into Phase 2

### Requirement: Export Validation Report [CAP-F-008]

The system SHALL copy Phase 1 outputs to a separate demos repository as a self-contained shareable artifact, SHALL generate a short outreach-friendly summary, SHALL refuse to run when Phase 1 output is missing, and SHALL optionally commit and render as PDF when those flags are set.

#### Scenario: Export produces a self-contained directory

- **Given** Phase 1 output exists under `.haytham/session/phase-1-why/`
- **When** the founder runs `/haytham:export --target ../haytham-demos --slug github-arslan70-haytham`
- **Then** the target directory contains `concept-anchor.json`, `idea-analysis.md`, `validation-report.md`, a `summary.md` generated by the outreach-summarizer agent, a `source.yaml`, and a `README.md`

#### Scenario: Export refuses without Phase 1 output

- **Given** no Phase 1 output exists under `.haytham/session/`
- **When** the founder runs `/haytham:export`
- **Then** the command refuses with a clear error message and does not write any files to the target directory

#### Scenario: Commit flag stages and commits in the demos repo

- **Given** the target is a git repository
- **When** the founder passes `--commit`
- **Then** the export command stages the new files and creates a commit in the target repository with a message naming the slug

### Requirement: Demo Pipeline [CAP-F-009]

The system SHALL accept a URL (Reddit post or GitHub repository), SHALL run validation in batch mode, SHALL export the resulting report with `--commit` to a demos repository, and SHALL produce one end-to-end log surfacing the verdict and the export path.

#### Scenario: Demo run on a GitHub repo

- **Given** the founder runs `/haytham:demo https://github.com/example/idea-repo --target ../haytham-demos`
- **When** the command executes
- **Then** the validation phase runs unattended, the export runs with `--commit`, and the founder sees one log with the verdict and the path of the committed report

#### Scenario: Demo refuses an invalid URL

- **Given** the URL argument does not resolve to a readable source
- **When** `/haytham:demo` runs
- **Then** the command stops at the validation step with a clear error and does not attempt export
